## سياسة الحذف الآمن

1. لا يُحذف `main` مطلقًا. ولا يُحذف فرع في PR مفتوح أو مغلق دون دمج، ولا فرع دون PR، إلا بعد قرار منفصل ومراجعة فروقه الحالية.
2. فروع `merged` **مرشحة للمراجعة** وليست مؤكدة الحذف: تحقق من SHA الحالي وتاريخ الدمج ومن عدم إضافة commits جديدة بعد الإغلاق. دمج `squash` يجعل سجل Git يبدو متفرعًا حتى حين تكون تغييرات الملف قد دخلت `main`.
3. ابدأ بحذف دفعات صغيرة من الفروع القديمة المؤكدة، واحتفظ بإمكانية استرجاع أي SHA معروف. لا تنفذ حذفًا جماعيًا غير قابل للتراجع.
4. أغلق أو دمج طلبات الدمج غير المحسومة فقط بعد إعادة تنفيذ اختبارات أحدث `main`، لا بناءً على نتائج قديمة.
5. إذا لم تكن آلية حذف الفروع متاحة عبر الموصل، تُنفّذ عملية الحذف من واجهة GitHub بعد مراجعة القائمة؛ **لا تدّعي حذفًا لم يحدث**.

## قواعد الفروع المستقبلية

- `main` للإنتاج.
- `feature/<domain>-<task>` لميزة جديدة.
- `fix/<domain>-<issue>` لإصلاح واحد.
- `refactor/<domain>-<scope>` لتنظيم الكود دون تغيير السلوك.
- `security/<domain>-<scope>` لتغييرات حدود الثقة والأمان.
- `docs/<topic>` للتوثيق فقط.

عند دمج PR ناجح وحسم التوافق، راجع إغلاق وحذف فرعه بمراجعة واعية، مع إبقاء تقرير الاختبارات في سجل PR.
