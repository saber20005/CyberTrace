# خريطة مستودع CyberTrace

> الغرض: توضيح أماكن الملفات والمسؤوليات قبل أي نقل أو حذف. هذه وثيقة للمستودع، لا تغيّر سلوك الموقع.

## الملفات والدلائل المعتمدة

| المسار | الوظيفة | سياسة التعديل |
| --- | --- | --- |
| `src/pages/` | شاشات الرئيسية غير الموجودة في App، المكتبة، التحقيقات، SOC وPro | يمكن تحسين الواجهة دون تغيير البيانات |
| `src/components/` | عناصر الواجهة المشتركة، بما فيها مركز تحليل الأدلة | افحص المستهلكين قبل النقل |
| `src/blackbox/` | ربط هوية BLACKBOX الثانوية والإيصالات وواجهة التقييم الخادمي | حدود ثقة حساسة؛ لا تستخدم البريد بدل UID |
| `src/data/` | التحقيقات وبيانات مناوبات SOC التدريبية | **مناوبات SOC المجانية قابلة للتصحيح محليًا وليست نتائج موثقة** |
| `src/utils/` | التقدم والتخزين والتوجيه والتقارير | لا تغيّر مفاتيح التخزين أو ترحيل التقدم دون اختبارات |
| `src/assets/` و`public/` | موارد البناء والملفات العامة وروابط المشاركة | لا تحذف الموارد المشار إليها في CSS أو JSX أو HTML |
| `api/` | واجهات Vercel الخلفية، منها ملخص الإدارة | تتطلب تحققًا خادميًا مستقلًا |
| `security/` | ملفات قواعد/محاكيات Firebase ومراجعة الأمان | مراجعة ونشر منفصلان عن Vercel |
| `tests/` | اختبارات Node ومنع الانحدارات | يجب تشغيلها قبل الدمج |
| `docs/` | أدلة الميزات والتشغيل والأمان | ابدأ من [فهرس التوثيق](README.md) |
| `.github/workflows/` | جودة البناء وفحوص Firebase | لا تُعطّل فحصًا لإتمام الدمج |
| `scripts/` | تدقيق بنية المستودع (دون تبعيات خارجية) | يُنفذ في CI |

## مسارات يجب أن تبقى ثابتة
- النطاق الإنتاجي: `https://cybertracelab.dev/`، وروابط `?view=...` و`?case=...`.
- مفاتيح تقدم CyberTrace الحالية، وتخزين دفتر الملاحظات وSOC عبر `progressKey`.
- ربط حساب BLACKBOX الاختياري القائم؛ حساب Firebase في CyberTrace **ليس** حساب BLACKBOX تلقائيًا.
- نتائج SOC-01/02/03 التدريبية لا تتحول إلى «نتائج خادمية» بمجرد النقل.
- `api/admin/summary.mjs` ومداخل Vercel و`index.html` و`vite.config.js`.

## خطوات نقل ملف مستقبلًا
1. اعثر على جميع `import` وروابط `src/href` وأي مسارات من اختبارات أو وثائق أو قواعد نشر.
2. انقل الملف في PR صغير، وحدث المراجع ضمن التغيير نفسه.
3. نفّذ `npm run check:structure` و`npm run lint` و`npm test` و`npm run build` وCI الخاص بـFirestore.
4. راجع رابط الموقع الحي بعد الدمج (إن كان النشر متاحًا). **نجاح GitHub لا يعني نشر Firebase**.
5. احتفظ بترحيل صريح وتغطية رجعية لكل مفتاح تخزين قديم.

## ما لم ننظفه عشوائيًا
- لا تُحذف قواعد Firebase السابقة لمجرد وجود أسماء `current` أو `emulator`؛ لكل ملف سياق نشر مختلف.
- لا تُمس وظيفة التقييم الخادمي قيد التجهيز قبل التحقق من App Check والمفاتيح الخاصة ومنع التلاعب.
- لا يُنقل مفتاح تصحيح أو ملف حساب خدمة إلى المستودع العام مطلقًا.

## المرحلة القادمة
تقسيم مكونات الواجهة الكبيرة تدريجيًا حسب المجال مع اختبار صارم للتقدم والمزامنة. لا تجرِ إعادة كتابة شاملة لمجرد أن أسماء الملفات كبيرة.
